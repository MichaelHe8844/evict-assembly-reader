# 1 引言

推理的显存与延迟主要由 KV 缓存决定；上下文超出预算时，必须裁掉大部分 token、只留很小一部分。对普通问答，压缩损失的多是冗余；对数值问答则不然：答案要从证据里**算**出来，而算的前提是数值与它的行头、列名、单位同时在场。

以真实例子说明。财报表格线性化后形如：

company | payments volume | total transactions  
american express | 637 | 5.0

问"每笔交易的平均支付额"，需要 637 与 5.0 两个数。按注意力挑 top-$k$（如 SnapKV[1]、H2O[2]）时，数值 token 的相对权重低于周边叙述词，往往只留下数值本身，行头"american express"与单位"billions"被驱逐：文本里仍有一个数字，却不再说明它是谁的量、以什么为单位，复算无从谈起。

这里有三点值得注意。数值到行头、列名、单位的最短距离在 FinQA 上要跨几十个 token，文档越长越糟；而注意力给数值 token 的权重又不到普通内容的一半（0.11 对 0.20），把打分调准并不能把结构补回来。更要紧的是保留单位本身：现有方法默认"保留什么"就是"保留哪些 token"，可表格里最小的可复算单位是一组，即数值连同它的行头、列名与单位。

这三点说的都是"还剩什么"。剩下的证据能否被**用对**是另一个问题：压缩只决定候选在那里，不决定读者会不会把候选组成正确的算式。紧预算下这一层被掩盖（没有证据就没有选择），宽预算下它才成为主要矛盾。

**定位。** 现有压缩方法问"哪些 token 重要"，本文问两件事：哪些数值及其绑定必须共存，预算不足时先保哪一组。做法是把结构信号固化为不可分割的**锚点组**、以闭包约束整组装入；再用离线训练的定位器在驱逐前把问题所需的操作数对钉入预算；最后把算术移出模型，读者只生成程序、由白名单执行器求值。

**贡献。**（1）**保留粒度**：保留对象由 token 提升为可复算的事实单元，在不改注意力信号的条件下精确匹配（EM）提升 13.0–44.9 点（$p<10^{-5}$；该增益主要来自整装，绑定本身提升的是可复算性，见 5.4）。（2）**任务相关选择**：区分"结构完整"与"这道题要的完整"，钉对单独贡献 +12.0 / +6.9 / +2.8 / +6.5 个百分点，完整新装配为 +29.2 / +18.1 / +10.2 / +6.5 个百分点；该层可独立叠加到现有注意力压缩器上。（3）**程序化读取**：读者只生成程序、由执行器求值，相对语言模型读者 +0.5 / +2.8 / +10.2 / +15.7 个百分点。三层的相对权重随预算改变：紧预算由取证决定，宽预算由读取决定。

全文组织：第 2 节综述相关工作，第 3 节定义锚点组与两个约束，第 4 节给出方法，第 5 节报告实验，第 6、7 节讨论与结论。

# 2 相关工作

**KV 缓存压缩。** 按注意力保留的一类（SnapKV[1] 的观测窗口 top-$k$、H2O[2] 的累计注意力加 sink）与按位置保留的一类（StreamingLLM[3] 的 attention sink 与最近窗口、Head+Tail 的首尾）共享同一前提："重要性可由注意力近似"；另有层间预算再分配[4]与低秩/量化压缩[5]，全景见综述[6]。近期有两条线放弃该前提：以删除后 next-token 分布的 KL 作判据[7]，或把驱逐改写为按未来效用学习的排序[8]。本文不与它们争判据，而争保留单元：即便判据完全准确，以 token 为单元仍会把数值与其行头、列名、单位切断。

**表格与数值文档上的压缩。** TableKV[9] 把 query-aware 与 query-agnostic 策略迁移到线性化表格，考察通用机制在表格上下文中的表现，未构造表格特有的保留单元，因而适合作为**token 级参照**（5.4 以其口径作为控制条件的起点）。NumCache[10] 则把保留单元从 token 提升到区域，为金融文档的数值密集区域构造数值保真 cache；但单元语义仍是"位置区间"，不是"可复算的事实"：不区分数值本体与单位、行头、列名，也不处理"单位常以独立片段出现、因而成为单点故障"。本文改的正是这一决策单元（3.4）。

**金融数值问答与程序生成。** FinQA[11]、TAT-QA[12]、ConvFinQA[13]、DocMath[14] 把答案锚定到单元格，Fin-RATE[15] 推进到 SEC 长文档，中文场景亦有对应工作[16]。与本文最接近的是 FINDER[17]：它把事实抽取与程序化思维链（PoT）拼成两步，同样以程序表示与精确执行完成求解；差别有三：其抽取在全文上进行、无保留上限，本文的证据被压到 3%–20%，抽取与保留是同一决策；其抽的是相关事实的自由文本，本文以四元组为不可分单元、装不下时按三级降级；其报告全上下文准确率，本文在同一预算下并列 PoT 与两种微调目标。PoT[18] 让模型输出程序、由解释器求值，FinQANet[11] 把操作数预测为单元格指针；选择性预测自 Chow 规则[19] 起有明确形式，SelectiveNet[20] 将其做成可训练模块，learning-to-defer[21] 把转交纳入学习目标。本文沿用这些表示，但把弃答的触发条件换成一个可复核的外部事实（证据里有没有这个数）。

**压缩条件下的训练。** Khodabandehlou 与 Krishnamachari[22] 用保留掩码与答案片段构造监督，证据存活时标 Confident、被移除时标 Abstain。差别在改什么。他们把"证据缺失"映射为弃答，本文保持答案不变、替换不可执行的程序；其判据是 span 的 token 存活率，本文的判据是程序内数值能否在证据中定位，属语义的、与分词无关的执行性判据。STaR[23] 确立了"自采样 + 按正确性过滤 + 重训"的范式；本文沿用范式而替换被监督的对象：过滤"能在这份压缩证据上执行的程序"。初步对照（见补充材料 S3）表明这一替换只在装配与训练证据不一致时才有可分辨收益，故与 STaR 的差别在判据不同、不在更好。

**证据可用性与可验证。** SRG-RAG[24] 指出长文本检索中的"语义平滑"会丢失微观特征，而在底层证据缺失时模型易受参数化先验干扰、诱发级联幻觉，该工作以图重排序加自反思把事实幻觉率由 22.4% 降到 6.2%；表格数据综述[25] 则说明表格是 LLM 应用中既常见又难处理的载体。这类工作问的是"证据是否被检索到、是否被正确使用"，本文问的是更前一步：**压缩之后还剩不剩可复算的证据**。数不在了，检索与阅读再准也无从兑现（4.3）。

# 3 数值锚点组

## 3.1 定义

现有方法以 token 为保留单位、以重要性为排序依据。对可复算而言，最小的不可分单位不是 token，而是让一个数值说得清自己是谁的那组成分：丢掉任何一个，它都退化成无法复算的孤立值。

对表格中的数值单元格 $v$，其**锚点组**为四元组 $\langle V,R,C,U\rangle$：$V$ 是数值本身，$R$ 是所在行的行头，$C$ 是所在列的列名，$U$ 是列对应的单位（如 `( billions )`）。$U$ 常以独立片段出现，因此是单点故障：丢掉它，数值的量级就不可判定。

**锚点组完整（ANR）** 指四个成分的 token 全部保留。**数值完整（NumR）** 只要求 $V$ 保留。二者的差就是"数字还在、但说不清是谁"的比例，记为 $P(\text{frag}\mid V)$。

**操作数闭包** 指完成一次运算所需的全部锚点组的并集。单步算术涉及两个操作数，二者所在的锚点组并成**一个**闭包；两个操作数常分处不同行或不同列，因此这个闭包一般不是单个十字。

用数值作语义锚点在语言建模中已有讨论[26,27]，本文的锚点不是单个 token，而是由表格结构确定的四元组：它既要能定位，也要能复算。

## 3.2 构成与代价

在 FinQA 调参段 300 个样本上，**单个**锚点组的 token 代价中位 2.9%、均值 4.1%、90 分位 7.2%；方法实际保留的不是单个组，而是一组候选锚点（列对冲与亚军候选会带来多个行列），其**并集**代价中位 8.8%、均值 11.1%，90 分位超过 20%。**约一成上下文承载了全部可复算证据**，这是本文方法的预算依据：20% 预算可容纳**多数样本**的锚点组（中位 8.8%、均值 11.1%），超过 20% 的长尾样本则触发 4.2 的降级链；剩余预算再按注意力填充。

## 3.3 保留问题的两种形式

**打分写法**取 $K=\arg\max_{|K|\le B}\sum_{t\in K}s(t)$，判据可为注意力、KL 或学到的效用（2 节）；对"可复算"，**约束写法**是一组硬约束：

$$K^{*}=\arg\max_{|K|\le B}U(K),\quad \mathcal{P}(q)\subseteq K$$

$$\mathcal{P}(q)=\bigcup_{c\in\mathrm{ops}(q)}g(c)$$

其中 $\mathcal{P}(q)$ 是问题所需操作数所在锚点组的并，$g(c)$ 是单元格 $c$ 的锚点组（3.1）。两者的差别不是打分器好坏，而是**约束是否在场**。

**（i）可行性。** 若 $B<|\mathcal{P}(q)|$，则任何策略都无法让 $q$ 可复算。这不是算法缺陷，是预算下界。这里 $\mathcal{P}(q)=\bigcup_{c\in\mathrm{ops}(q)}g(c)$ 是所需锚点组的**去重并集**：不同数值常共享行头、列名或单位，因此按组求和会高估代价，须以并集的 token 数计。由 3.2 的单组代价（中位 2.9%）可得两操作数题的**经验预算尺度**约为 **6%**。这个数是按中位数推出来的标尺，不是定理；在 test 216 题上按 4.2 的装配实测，四档 ANR 为 **0.111 / 0.255 / 0.593 / 0.866**（3%/5%/10%/20%）。最陡的一跳发生在 5% 与 10% 之间，正好跨过这个尺度；两条增益曲线在 10% 档取值接近（10.6 对 10.2），到 20% 档发生反转（7.9 对 15.7，5.3）。

**（ii）不可互替。** 打分形式即使打分器完全准确，也不保证 $\mathcal{P}(q)\subseteq K$：只要 $\mathcal{P}$ 内某个成分的分数落到第 $B$ 名之外，它就被挤出。这不是假设：实测注意力给数值 token 的权重只有内容 token 的约一半（见 1 节观察 2），故打分器**系统性**地把操作数排在后面；而约束形式按构造成立。

**（iii）理想与实现。** 上式中的 $\mathcal{P}(q)$ 由 gold 操作数给出，是**理想约束**；实际系统无从预先知道金标，只能用一个离线训练的定位器 $\pi_\theta$ 预测一对单元格，再展开成约束 $\tilde{\mathcal{P}}(q)=\bigcup_{c\in\pi_\theta(q)}g(c)$。二者之间有三类偏差，且都可测：（a）**定位错误**——$\tilde{\mathcal{P}}(q)\neq\mathcal{P}(q)$，由成对命中率刻画（5.2）；（b）**预算不可行**——$\tilde{\mathcal{P}}(q)$ 的代价超过 $B$；（c）**降级本身**——不可行时按 4.5 的三级规则丢绑定、保数值，证据虽在而绑定不全。三者之和解释"约束成立"与"约束兑现"之间的差距；上界分析中的池召回 $R_B$（见补充材料 S2）正是这一段的可观测版本。

本文因此不改进打分器，而改形式：4.2 给出约束缺席时的整段降级规则，4.5 给出生成 $\mathcal{P}(q)$ 的定位器，5.2 与 5.4 分别量出约束在场与缺席时的差距。

## 3.4 两个约束：结构完整性与任务相关性

前两节把"保留什么"写成约束，但其中压着两个不同的条件，必须分开：

- **结构完整性（闭包）**：$G(v)\subseteq K$。只要数值 $v$ 被保留，它的锚点组就必须整体保留。这是对**单个事实**的自洽条件，定义"什么才算一个可保留的整体"。
- **任务相关性（优先级）**：$\mathcal{P}(q)\subseteq K$ 先满足。在完整的整体之间，先装这道题所需的那几组。这是**跨事实**的选择条件，定义预算不足时"哪个整体先装"。

二者互不蕴含，两个方向都有反例：

（1）**完整却不相关**。一组锚点可以完全完整、却与当前问题无关。AUA（5.4）正是这种状态的实现。它把注意力聚合到锚点组、整组保留，**对能被整组装入的锚点**闭包成立；表 4 的 ANR 未达 1，说明并非所有被保留的数值都满足完整闭包。但它没有"这道题要哪一组"的概念：表 4 显示它能把组级保留的基线抬高（20% 档 0.069 → 0.519），却不具备选择能力。引入问题相关信息后，同一管线内的 EM 由 0.556 升到 0.634（表 3）。两组数字取自不同实现，故此处只作定性对照，不作相减。
（2）**相关却可能不完整**。定位器找对了数值，并不保证它的行头、列名、单位留在预算内：紧预算下钉对会挤掉绑定，4.5 的三级降级正是这一冲突的可观测形式，3.3(iii) 把它记作三类偏差中的两类。

因此本文求解的不是一个优化问题，而是两个：**以闭包为可行域、以相关性为优先级**。第一项决定"值得整体保留的是什么"，第二项决定"装不下时先要哪一个"。三层的顺序也因此不能颠倒——粒度定完才谈得上选择，选择定完才谈得上读。

# 4 方法

本节分两侧。4.1–4.5 是**取证侧**：决定压缩之后还剩什么，方法上不含训练（4.5 的定位器离线训练一次），推理期只做抽取与装配。4.6–4.7 是**读取侧**：决定给定证据之后答得对不对，主方法是 4.7 的编译式读者，4.6 的两阶段读取是它的**对照**。两侧的收益随预算**交叉**（表 3）：紧预算受限于证据、宽预算受限于读取方式，交叉点约在 10%——这正是本文把两侧分开报告的理由。

**问题与符号。** 记文档 $D=\langle P,T,Q\rangle$，$P,Q$ 为表格前后的叙述，$T$ 为表；表中数值单元格 $c$ 携带四个成分——值 $v(c)$、行头 $\rho(c)$、列名 $\kappa(c)$、单位 $\upsilon(c)$。给定预算 $B$（文档区间的保留比例）与压缩器 $\pi_B:D\mapsto K$（$|K|=B$），阅读器 $f:(q,K)\mapsto\hat a$ 的任务是回答问题 $q$，评测量为 $\mathrm{EM}=\Pr[f(q,\pi_B(D))=a]$。问题 $q$ 的金标操作数格记为 $\mathcal{G}(q)$，单步题时 $|\mathcal{G}|=2$。

**损失分解。** 把"答对"拆成两个可分别测量的因子。对任何**只在候选池内取值**的阅读器，$\mathcal{G}(q)$ 不在池中时精确定位不可能发生，于是

$$\mathrm{EM}=R_B\cdot E+(1-R_B)\cdot E_{\varnothing},\qquad E_{\varnothing}=\Pr\big[\text{答对}\mid\mathcal{G}(q)\not\subseteq\mathcal{C}_K\big]$$

其中 $\mathcal{C}_K$ 为从保留集 $K$ 恢复的候选池（4.5），$R_B$ 称**池召回**、$E$ 称**兑现率**，$E_{\varnothing}$ 是**缺失项**——操作数不在池里却蒙对的概率。三项式按全概率展开，**恒成立**；两项式 $\mathrm{EM}=R_B\cdot E$ 只是 $E_{\varnothing}=0$ 时的特例。本文在 5.3 实测了缺失项：在 gold 操作数已从 20% 证据中消失的 19 道题上，三种读者的 EM 同为 **0.053**，即 $E_{\varnothing}\approx0.05$，不严格为零——所以后文一律用三项式，两项式只在做近似说明时出现。两条性质构成后文的骨架：

- **P1（分解）**：三项按全概率恒成立。$E_{\varnothing}$ 固定时，可动的是两条互不替代的路径——抬 $R_B$（改压缩器或选择器）或抬 $E$（改阅读器）。$E_{\varnothing}$ 本身**不是改进目标**：它描述"操作数已缺失时还能蒙对多少"，数值越高 EM 反而越高，因此不能当作"压低即改进"的旋钮。本文只把它当**诊断量**——5.3 实测三种读者在缺失子集上同为 0.053，说明缺数时几乎只剩运气。$\mathcal{C}_K$ 的取法随读者而定：对算法 1 这类**只在候选池内取值**的阅读器，$\mathcal{C}_K$ 是候选池，$R_B$ 即池召回；对直接读压缩全文的语言模型，$\mathcal{C}_K$ 取保留文本自身，$R_B$ 即文本通道上界（见补充材料 S2）。两者的差别只在"可得证据"的边界，分解形式不变，因此那一组分析报的是同一个量在两个读者上的实例。
- **P2（兑现率的预算不变性，经验）**：在本文训练的读者上，$E$ 在 $R_B\ge0.5$ 的区间内稳定在 0.55–0.63，而 $R_B$ 随预算跨一个数量级（0.842 $\rightarrow$ 0.079）；紧预算档的损失几乎全部由 $R_B$ 承担。P2 由池召回与兑现率的实测验证，是**经验性质而非定理**，适用范围写在该节的边界段。

**方法总览。** 方法分两侧，并把"离线训练"与"推理期使用"分开看。压缩侧的抽取与装配**不含训练**，只在推理期运行；读取侧有两处需要**离线训练**：4.5 的定位器（33M 交叉编码器，编码器全量微调）与 4.7 的编译式读者（3B + LoRA）。两者都在推理之前一次完成，推理期只做前向、不再改权重。压缩侧：(i) 从表格结构无监督抽出**数值锚点组**（4.1）；(ii) 按单元整段装配预算（4.2）；(iii) 预算装不下锚点集时，由**驱逐前的学习式定位**决定"哪两格必须一起保留"，并作为硬约束并入保留集（4.5）。读取侧：(iv) **主流程是生成程序、由白名单执行器求值**——读者在压缩证据上一次自回归生成可执行程序，由脚本精确求值，执行失败即判错（4.7，算法 1）；**两阶段读取**（复用 4.5 的编码器，推理期只做前向）作为**对照**放在 4.6，用于说明"先选一对、再判算式"与"直接生成算式"两种读取流程的差别。**压缩侧决定 $R_B$，读取侧只决定 $E$**，这是 P1 的直接推论，也是本文把两件事分开报告的理由。4.3 的 AIR 与 4.4 的候选重排用于解释与界定方法，不承担增益。

## 4.1 无监督锚点抽取

输入是线性化后的文档片段序列，每个片段带有类型（表头、列名、行头、数值、单位、正文）。抽取分三步：

第一步按分隔符还原行列坐标，得到"第 $r$ 行第 $c$ 列"的单元格索引，以及行头表与列名表。

第二步给每个列名打分：分数来自它与问题的词面重叠，另加三条规则——前缀模糊匹配（`total`/`totals`）、年份匹配（`december 31 , 2016` 这类日期型表头）、列对冲（两个候选列分数接近时都留下）。其中年份匹配最管用：首版 99% 的列名失败都出在日期型表头，这类表头的内容词只剩 `year`，词面匹配无从下手。

第三步把选中的行与列叉乘得到单元格，再补齐各自的行头、列名、单位。无监督分数不够时保留"亚军候选"：金标行有 26%、金标列有 21% 排在第 2 名，它们分数并不低，只是没到阈值。

在 FinQA 原始问题上，完全召回 **0.917**、token 覆盖 1.000、抽出的锚点集代价中位 8.8%（留出段 0.893）。

## 4.2 锚点优先的预算分配

给定预算 $B$（文档区间的保留比例），分配按优先级链进行：

1. **装锚点组**：按优先级链整段装入、绝不切开一个成分——链的顺序可配置（表头优先或数值优先），5.2 给出两者的剂量反应，本文默认取**数值优先**；
2. **装不下则整段降级**：从锚点组退到十字（行$\cup$列）、退到行/列切片、最后退到单个单元格——每次退一个层级，而不是逐 token 淘汰。操作数闭包只出现在金标分析中，自动流程并不知道"这道题需要哪两个操作数"，因此装配阶段也不以闭包为单位；
3. **剩余预算按注意力填充**：用 SnapKV 分数补齐，保持与基线在同一预算下可比。

第 2 条的动机：逐 token 淘汰极易切碎某个成分，而整段降级的失败是"整个事实不在"，可被 AIR 检出、也可被上层拒绝作答。

**为什么不在求解器上投入。** 先看不带约束的形式：只要求"装得下"时，"先装谁"是一个带并集代价的 0-1 规划——在 $\big|\bigcup_{x_i=1}T_i\big|\le B$ 下极大化 $\sum_i w_i x_i$，其中 $x_i\in\{0,1\}$ 表示第 $i$ 个锚点组是否装入。

把分配器换成密度贪心（均匀或相关性权重）、仅按相关性排序、按静态密度排序，三者两两差异在四档上都不显著（最小 $p=0.078$），但都显著优于"按类装箱"：3%/5%/10% 分别高 $+22.6/+26.0/+14.6$ 个百分点（$p<10^{-4}$）。原因是 20% 档有 82% 的文档已饱和（$B\ge|\bigcup_i T_i|$），任何整段装入都最优。**并集代价的精细求解在这个规模上不兑现收益，而"整组装入 + 相关性排序"已经兑现。** 本文因此把重点放在约束（3.3）而非求解器。

## 4.3 AIR：结构完整性的诊断指标

$$\mathrm{AIR} = \frac{\big|\{c \in \mathcal{C}_{\text{ret}} : R(c), C(c), U(c) \text{ 均被完整保留}\}\big|}{|\mathcal{C}_{\text{ret}}|}$$

其中 $\mathcal{C}_{\text{ret}}$ 是被保留下来的、本可绑定的数值单元格集合。AIR 不需要 gold，只需要表格结构与保留掩码。它的语义是**文档级健康度**：回答"留下来的数字里有多少还带着复算所需的绑定"，不回答"这道题的答案还在不在"。实际报告时取 $1-\mathrm{AIR}$（**断绑率**）更直观，但必须与 NumR 及"分母非空的样本比例"同报。

## 4.4 问句→单元格定位模块

压缩后的主要失败形态不是"数字被删"，而是"找到了一格、没锁定另一格"。据此给一个不训练、不增加前向的模块：只读保留的单元格，按行头与列名的词面重叠（含单复数归一、年份对齐）打分，取 top-$k$ 渲染成带 ID 的候选，模型只输出 `C1 - C2` 形式的引用，脚本按候选表展开真实数值。

它把"在整张表里找一个数"改写成"在少量候选里挑两个"，顺带消掉复述数字的转写错误。**但实测收益被下一层截断**（5.2）：成对定位率显著上升，准确率几乎不动。故只作诊断工具与边界证据。

## 4.5 驱逐前的学习式证据定位

前面几节默认"保留什么"由规则决定。紧预算下这条假设不成立：5% 预算时锚点集本身常常装不下，实测只有 29.8% 的样本能同时保住两个操作数。此时决定成败的不是"怎么分配"，而是"哪两格必须一起留下"。

定位器在**驱逐之前**运行——那一刻整张表都还在上下文里，因此它可以读全表，不必受保留集限制。给定问题 $q$ 与候选格集合（整表按行头/列名相关性排序的 top-8），对每一对打分：

$$s_\theta(q,c_i,c_j)=\mathrm{MLP}\big(\mathrm{ENC}(x)\big),\quad x=[q;d(c_i);d(c_j)]$$

其中 $d(c)$ 是"行名 | 列名 (单位) = 值"。训练标签为"这一对是否覆盖全部金标操作数"，数据取 FinQA 训练集的单步题（1374 题、35,551 对，正例 3.6%），与评测的 dev 按文档切分、零重叠。推理取 $\arg\max$，把选中的两格连同它们的行头、列名、单位并入保留集；定位器只输出**位置**、不输出数值，模型看到的内容仍然只有被保留的那部分。

**成对形式的作用在别处。** 两格放进同一条序列并不比逐格打分更准（dev 0.596 对 0.561，test 0.566 对 0.582，均不显著）；它的价值是一次前向给出整对分数，起作用的是问题与单元格的交叉交互。

实现细节：编码器为 bge-small-en-v1.5（33M），损失为带 `pos_weight` 的 BCE，batch 16、编码器学习率 $2\times10^{-5}$、头部 $10^{-3}$、OneCycle、6 个 epoch；训练集内部再按文档切验证集挑 epoch，dev 与 test 从不参与任何选择，阈值也不在评测集上调。推理时把 top-8 候选的 28 对拼成一个 batch 一次前向完成。

本文也试过显式关系建模：在编码器之上按 token 位置取出两格各自的池化向量，并加 $|h_A-h_B|$ 与 $h_A\odot h_B$ 交互项。同脚本、同协议、同种子的三组对照（合并 296 道未见题）为 0.581（仅 [CLS]）、0.574（+逐格池化）、0.564（+交互，$p\geq0.38$）——**交叉编码器已隐式学出两格关系，显式交互项无增益**，故不采用。

它与 4.2 的分配是两个不同的问题：4.2 问"给定预算先装谁"，是**分配**；这里问"哪两格必须一起在"，是**识别**。前者的消融是否定的（预算越过锚点集后装配方式不再有区分度），后者只在紧预算下才成为主要矛盾（5.2）。

**装配与回退。** 选中的一对在装配阶段作为最高优先级：先整对装入（两格数值 + 各自的行头、列名、单位），再用剩余预算按 4.2 的优先级链装其他锚点，最后按注意力补满。若整对装不下，按三级回退——先丢绑定成分、只留两格数值，再只留一格，最后放弃——并记录回退落在哪一级。**因此每个样本的保留 token 数恰好等于预算 $B$，与基线逐样本同预算**；代价是证据完整性不再是无代价的，装不下就必须降级（5.2 报告各级比例）。

## 4.6 两阶段读取：对照与复杂度

错误分析把读完证据后的失败切成三段：已定位的两个操作数，模型**选中**只三成；选对了**算式定不对**只三成半；算式对了**算不对**只两成。三段都不是"没读到"，而是读完之后的处理；这与 GRAB[28] 的结论一致：剩余损失集中在算式构造与求值。

据此给出一个把三步分离的**对照**模块：它在保留的候选格上工作，输入是每格的行头、列名、单位与数值（不含原始文本），输出"选哪一对、做什么运算"，答案由脚本精确求值。结构为 bge-small 编码器加两个头（成对打分、八类算式），以 gold 程序监督；算式标签不解析官方算子串，而用 gold 两格的值试八个算式、取能还原答案者，故多步题不进入训练。运算类型由八类头判定，论元方向则交给三条问句模式：百分比类取含 `total` 的格，`ratio of X to Y` 取 $X$，`from X to Y` 取 $Y$。这些规则不含参数。不用分类头学方向：配对正确后算子仍错三成，其中 76% 是 $a/b$ 判成 $b/a$，而这些题 88% 的问句已有线索。

流程为两阶段：先在候选池里以一次前向选出一对格，再在该对上判算式并精确求值；候选不足两个时回退语言模型，但**本文所有数字都不启用该分支**——$R_B$ 低时它在可尝试子集上也不如语言模型（3% 档 0.158 对 0.474），回退只用来把边界写出来。该模块不改变缓存，只改变"谁来算"，因此与 4.1–4.5 正交；其收益严格依赖池召回，有效区间在 $R_B\ge0.5$（见补充材料 S2）。**复杂度**：抽取与装配各一次线性扫描，读取为 $O(m^2)$ 次短前向（$m=8$，单题 28 次），与文档长度 $n$ 无关，故读取成本相对 $n$ 为 $O(1)$；这与"让语言模型再读一遍上下文"的 $O(n^2)$ 有结构性差别，是本文方法能外推到长文档的前提。

## 4.7 编译式读者：训练与执行

4.6 的两阶段读取有两个内建上限：候选只来自保留集（池召回 0.76–0.82 封顶），且只在八类预定义算式中挑（多步题无法表达）。若要让读者利用正文里的数与任意组合，就必须把"从固定集合里挑"换成"自由写一个程序"。

**形式。** 给定压缩后的证据 $\mathrm{tok}(K)$ 与问题 $q$，读者输出程序 $p$，答案 $\hat a=\mathrm{Eval}(p)$，其中 $\mathrm{Eval}$ 是白名单执行器（只允许八类算术算子与数值字面量）。训练目标为

$$\max_{\theta}\ \sum_{(q,K,p^{\ast})\in\mathcal{T}}\log \pi_{\theta}\big(p^{\ast}\mid q,\ \mathrm{tok}(K)\big)$$

其中 $K$ 是文档 $D$ 在某一档预算下的压缩证据，$\mathcal{T}$ 由四档各取一遍构成（6500 条）。

与 4.6 的差别在**输出空间**：4.6 的输出是 $\binom{m}{2}\times 8$ 个离散选项，4.7 的输出是任意长度的程序串，因而能表达 4.6 结构上表达不了的组合；代价是它需要训练，且生成可能失败。

**实现。** Qwen2.5-3B-Instruct，4-bit nf4 双量化加 LoRA[29]（$r=16$、$\alpha=32$，作用于四个注意力投影），可训练 **7.4M**；训练集为 1625 道单步题在四档预算下的压缩证据（6500 条，前缀预算标签），**证据按 4.2 的装配生成（先数值、后绑定），与推理端一致**；钉对只在推理侧做，因为定位器在 train 上训练过，对 train 打分属样本内。batch 1 × 累积 8、学习率 $2\times10^{-4}$、最大长度 896、梯度检查点。单卡 RTX 4060 Ti 16 GB，峰值显存 **9.2 GB**；训练在压缩证据上进行，812 步约 40 分钟（约 2.9 s/步）。**档位标签**：训练 prompt 以档位标签（`预算：b`）开头，评测端未加；20% 档 126 题对照为 0.651 对 0.667（2 道翻负、0 道翻正），属噪声，正文读数不受影响。

**执行器。** 八类算子加白名单校验；FinQA 程序中的 `const_5` 记号统一还原为数值（dev 中占 **17.8%**，不处理会系统性压低任何执行口径下的基线），中缀写法截断到等号前。**无法执行即判错，不给部分分**——与 4.7 完全一致。

**算法 1 编译式读取（单题）**

| 行 | 操作 |
|---|---|
| 1 | 输入：问题 $q$、压缩证据 $K$、预算档 $b$ |
| 2 | 按模板拼 prompt：档位 $b$、压缩证据 $\mathrm{tok}(K)$、问题 $q$，以"式："收尾 |
| 3 | $p\leftarrow\pi_\theta(\cdot\mid\text{prompt})$ — 一次自回归生成，贪心，上限 40 token |
| 4 | **return** $\mathrm{Eval}(p)$ — 白名单执行器；不可执行即判错，不给部分分 |

三行是本文的主方法：第 3 行产出程序，第 4 行将求值交由确定性执行器。**证据溯源不在这个框里**：第 3 行的程序只保证可执行，不保证每个数都取自证据。要加这一层，需在生成与求值之间插入一次校验与弃答（不通过或输出 `ABSTAIN` 时转交语言模型）；本文主算法不含这一步。

**另一版监督（消融）。** 已知的一个替代做法是执行反馈自训练：用基准读者在同样的 prompt 上自采样（每题 5 条），只保留**执行通过且答案正确**的程序，再从同一底座、同一配置重训一次。它不混入 gold，判据只有"能执行、算得对"。本文按同一配置训练了这一版（见补充材料 S3）：**它与 gold 监督在四档上不可分辨**，因此主结果一律用 gold 监督，这一版只作为消融出现。

**分工。** 4.6 是 $O(m^2)$ 次短前向、与文档长度无关，推理期不训练；4.7 是一次自回归、成本随输出长度（约 8 token），但需要训练。前者适合"候选已足够准"，后者适合"证据里有却没被选进候选"；5.3 的交叉正是这两种失效模式的交界。

# 5 实验

## 5.1 设置

**数据。** FinQA[11] dev（883 条）：用 `qa.steps` 的数值实参与 `ann_table_rows` 定位 gold 单元格，得 848 条可构造锚点组的样本（55.4% 单步）；第 1–400 条用于开发，第 401–848 条留作检验。读取侧用官方 test：1147 题中 `build_dataset` 能解析表格与 gold 单元格者 555 题，再要求程序为单层函数调用、答案可解析、按（题号，答案）去重、文档长度落在 64–1100 token，得 **216 题**。其中 **34 题**在 20% 压缩后候选不足两个、无对可钉，其分数不计入钉对与装配增益（20% 档三种读者为 0.088 / 0.059 / 0.176，确实更难）。训练取 FinQA train 的 **1625 道单步题**，四档预算各出一条样本，合计 6500 条。

**上下文构造。** `pre_text` + 行式线性化表格 + `post_text`。不用官方 `model_input`：它把单元格渲染成自足句，绑定天然不断，会使研究对象消失。

**样本单位。** 每题只取第一个 gold 单元格，所有条件共用同一锚点，从而"每题一个二元结果"，EM 与 McNemar 都在唯一问题上计算；代价是其余锚点未利用。各实验样本量不同（主表 216、装配顺序与剂量反应 126、三臂对照 182、候选引用 56），**绝对准确率不可跨实验横比**。

**模型与任务。** 3B 在全上下文下自由作答的真实算术 EM 为 0，故读取侧统一用 **PoT 脚手架**（模型先出算式、由脚本求值）使其脱离地板；读者为 4.7 的 Qwen2.5-3B-Instruct + LoRA，与语言模型基线同底座。同卡 RTX 4060 Ti 16 GB，`eager`。

**条件、指标与口径。** 装配有两套：$\mathcal{A}_0$（4.2 的装配取**表头优先**顺序、无钉对，即旧基线）与 $\mathcal{A}_1$（4.2 取**数值优先**，并把定位器选中的一对钉入保留集，5.2）。预算只作用于文档区间，问题与指令不裁剪；所有条件保留 token 数由 $B=\lfloor k\cdot n_{\text{doc}}\rfloor$ 决定、逐样本相同，强制保留也在 $B$ 内装配，装不下按 4.5 回退。所有条件共用一次 prefill、按掩码裁剪各层 key/value（保留原始 RoPE 位置），在同一代码版本与同一贪心解码路径下重跑，裁剪 0 个位置时 $\max|\Delta|=0$。指标为 EM、NumR、ANR 与 $P(\text{frag}\mid V)$。表中保留三位小数，正文增量按未舍入记录计算，故用表内数值相减可能差 0.1 个百分点；区间按文档聚类 bootstrap（3000–4000 次）。

## 5.2 装配顺序，以及在预算内钉住一对

**第一件决定紧预算结果的事不是打分，而是装配顺序。** 4.2 的装配按"列名/单位 → 行头 → 数值"整段装入：20% 预算下几乎无害，但 3%–5% 只够装十来个成分时，表头会先吃光预算、数值被整段丢弃。把优先级改成"先数值、后绑定"，同一批 126 条记录、同一预算、同一抽取器（表 1）：

**表 1 装配顺序的剂量反应（126 条单步记录，3B）**

| 预算 | 只保数字 | 先数值后绑定 | 旧顺序（表头优先） | 先数值 vs 旧顺序 |
|---|---|---|---|---|
| 3% | 0.230 | 0.270 | 0.071 | $+19.9$pp（$+28/-3$，$p=5\times10^{-6}$） |

预算越紧，顺序越重要：3% 与 5% 档的增益是决定性的，10% 以上与噪声同量级。这解释了一个容易被误读的现象——同一套锚点组在 5% 下按表头优先装配只得 0.159，看似"结构化保留不如直接保数字"，实为预算被标签吃掉。改正顺序后，本文与"只保数字"四档统计不可分（$+5/-0$、$+3/-2$、$+4/-5$、$+1/-4$，$p\ge0.06$），最紧的 3% 档方向还偏向本文；ANR 则由 0.00 / 0.00 / 0.00 / 0.07 升到 0.06 / 0.16 / 0.60 / 0.84。这与 4.5 的降级链是同一件事的两面：降级链决定装不下时先丢什么，装配顺序决定预算不够时先保谁，规则同为**数值优先、绑定次之、可复算性随预算恢复**。

失败形态给出第二个对策：既然损失来自操作数被拆散，就让定位器先决定哪两格必须一起留下，装配阶段把它们钉进保留集。**学习能否被规则替代。** 命中率不等于收益：挑对了但装不进预算、或挤掉别的锚点都不兑现。5% 档的三臂对照（182 题，即 216 减去那 34 道无对可钉者；同一 PoT 读者与预算、只改"钉哪一对"）：不钉对 0.451；手写规则 0.412（$+10/-17$，$p=0.25$）；学习式 **0.484**（$+20/-14$，$p=0.39$）。两两之差只有一处可测：**学习式相对规则 +7.1**（$+24/-11$，$p=0.041$；聚类区间 $[-0.5,\ +15.4]$，下界贴 0）。该 $p$ 值未作三臂多重比较校正（Bonferroni 阈值约 0.017），校正后不显著，只作**方向性证据**。分两层看：任一侧相对"不钉对"都不显著且方向相反，**钉对并非普遍有效，定位错时会损害性能**；同一件事由规则改由学习差 7 个点，**手写规则替代不了定位器**。

## 5.4 保留粒度：从 Token 级到锚点组级

**要分开的两件事。** 前述压缩器基线都在 token 上按注意力取舍。TableKV[9] 把同类策略迁移到线性化表格，是"表格语境下最接近的参照"，但其作者明确声明该工作尚**不含表格特有的结构策略**，故它只提供 token 级对照，不构成"以表格事实为保留单位"的方法。要回答"增益来自保留粒度还是问题相关选择"，需要一次控制实验：保持注意力信号、模型、读者、数据与逐样本预算不变，把"token 级 top-$B$"换成"组级聚合 + 整组保留"——这一步同时改变分数聚合与整装方式，故按**整体效果**报告。

**三个条件。** （i）**TableKV-tok**：token 级注意力 top-$B$；（ii）**AUA**（Anchor-Unit Attention）：把组内注意力聚合成锚点组分数、以组为不可分单位整组保留，余量按注意力填充——本文构造的结构粒度控制变体，不是 TableKV 原文方法；（iii）**词面（组级）**：同为组级整装，只把排序信号换成行头/列名的词面相关性。三者共用同一底座、读者、216 题与预算。

三个条件在同一进程内测得、逐题配对，**同一预算下的三个条件可直接比较**；它们与表 3 使用不同的证据构造实现，**绝对值不可跨表相减**。

其一，**保留粒度是这一组对照里最大的一项**：token 级注意力 top-$B$ 换成锚点组级聚合 + 整组保留，得 **+0.130 / +0.278 / +0.417 / +0.449**，配对 +32/−4、+62/−2、+92/−2、+97/−0，$p<10^{-5}$。这是"锚点组级保留策略的整体效果"（同时改变聚合与整装），本文不把它单独归因于四元组定义；可分辨的机制是 token 级保留在紧预算下几乎留不下完整锚点组（3% 档 ANR 为 0），组级整装则把"留下的是不是一条可复算的事实"变成可控量。

其二，**组级整装固定后，排序信号的影响相对较小**：注意力聚合相对词面排序的增益为 **+0.9 至 +7.9**（+4.2 / +4.6 / +7.9 / +0.9），配对 +23/−14、+27/−17、+18/−1、+3/−1，**仅 10% 档显著**（$p<0.01$），其余三档区间含 0。四档方向一致但幅度远小于改变粒度，本文不据此声称两者等价——那需要预设等效界的等效性检验。

其三，**问题相关定位有独立增量，量级小于整体装配改造。** 在同一"先数值后绑定"装配上只做 ± 钉对的对照，EM 由 0.333 / 0.412 / 0.468 / 0.514 升到 **0.454 / 0.481 / 0.495 / 0.579**。增量为 **+12.0 / +6.9 / +2.8 / +6.5**，四档区间依次为 [+4.3, +20.2]、[+0.5, +13.7]、[−2.7, +8.5]、[+2.6, +11.5]；逐题翻转 +39/−13、+25/−10、+14/−8、+14/−0，3%、5%、20% 三档显著。表 3 的 $\mathcal{A}_0\to\mathcal{A}_1$ 同时改变顺序与钉对，其 +28.2 / +20.8 / +10.6 / +7.9 不能记在钉对名下：紧预算下大部分增益来自顺序，钉对解释其中较小的一部分。

**另作一组对照：只改保留形状、不动整装。** 准确率几乎不动，可复算性却大变。 同一抽取器与 20% 预算下把保留形状换成"只保数字""整行""整列"（7B/8-bit，117 题，见补充材料 S1）：四者 EM 为 0.393–0.410，彼此差 1–2 道题、全不显著（只保数字 4:4，$p=1.0$），ANR 却由 0.085 升到 0.906（整行 0.590、整列 0.573）。可见**整装买的是准确率，四元组定义买的是"留下的数说得出自己是谁"**（4.3）；干预同向：把绑定 token 的 value 在 36 层置零，3%/5% 档 EM 与清零前完全相同。

**边界。** TableKV 原文在 7–8B 模型与不同任务形态上评测，本节不复现其绝对数值、只复现保留机制；AUA 为本文按锚点组定义构造的控制变体，非任何公开实现。

## 5.6 小结

三组实验对应三条贡献，量级依次递减：**保留粒度**（+13.0 至 +44.9 点，$p<10^{-5}$）、**装配与钉对**（端到端 +29.2 至 +6.5，四档区间不含 0；钉对单因素 +12.0 至 +6.5）、**读者替换**（+0.5 至 +15.7，宽预算显著）；跨底座在 Llama 上复现同一次序。受篇幅限制，可复算性前提（117 题）、文本通道上界与兑现率（87 题）与增益归因未在正文展开，详见补充材料 S1–S3。

# 6 讨论

## 6.1 边界与定位

**第一条是粒度，不是精度。** KV 压缩的瓶颈不能归结为"重要性打分不够准"：打分器即使完全准确，也只有排序、没有约束（3.3），数值、行头、列名与单位仍会被分别驱逐。5.4 的控制实验把两件事分开：改变保留单元带来的增益远大于改进组级排序信号，后者只在单一预算档显著。**改变决策单元比改进排序更重要。**

**第二条是结构完整不等于任务相关。** 每个组都能完整表达一条事实，预算仍可能装满与当前问题无关的事实。学习式定位器把所需操作数对钉入预算后，同一"先数值"装配上得 +12.0/+6.9/+2.8/+6.5，完整新装配为 +28.2/+20.8/+10.6/+7.9。装配顺序解释大部分增益，钉对解释其中较小的一部分。三层因此不可替代：粒度决定事实结构能否存在，排序信号决定候选先后，任务相关定位决定预算先服务哪一次计算。

**第三条是学习的位置。** 结构信号被固化为不可分割的保留单元，而不是揉进标量分数。学习只在离线出现三处（4.5 的定位器、4.6 的编码器、4.7 的读者），判断"这个格是不是题里要的量"，与注意力无关；分配器因此很简单：单元对了，只需整段装入。

**与公开结果的位置关系。** FinQANet 与 FINDER 在**全量 test、全上下文、更大底座**上评测（执行准确率 61.24% 与 75.32%，前者单步程序子集 67.61%）；本文在 3B、3%–20% 压缩下评测，条件不同，故不作同表比较。就单步这一步而言，本文 20% 档的 63.4% 与 FinQANet 单步子集的 67.61% 同量级，可作外部量级参照，不构成优劣结论（口径差异见 6.2）。

## 6.2 适用条件

结论限于 3B 级模型、英文财报的单步数值问答与官方 test 的 216 题。七条限制同时成立：定位器只在 Qwen 上训练，跨底座精度未单独测量（5.5）；20% 档装配已饱和（4.2：82% 的文档在该档装得下全部锚点组），两种装配在该档的差别随之收窄，故增益空间有限——取证收益因此集中在 3%–10%；监督只做单轮消融，见补充材料 S3；外部压缩器只测 SnapKV 与 H2O 两类（见补充材料 S5），结构粒度化的控制变体（AUA）只作基线（5.4）；多步题依赖执行器的格式扩展，见补充材料 S4；证据构造依赖行式线性化，跨版式未验证；**未与公开方法做同指标对比**（6.1 只给量级参照，模型规模与证据条件不同）。

# 7 结论

本文的结论是一句话：**压缩预算决定数值问答的瓶颈落在哪一侧**——紧预算由证据能否被正确保留决定，宽预算由读取方式决定，两条增益曲线的方向相反。

由此得到四条可操作的做法。其一，保留单位应按可复算事实划分而非按 token，粒度先于打分精度。其二，闭包只保证事实自洽，预算分配还需问题相关的优先约束，二者不可互替。其三，算术应交给确定性执行器，读者只负责把证据连成程序；程序越深，替换的收益越大。其四，装配顺序比读取方式更早决定结果，因此取证与读取应分开评测。

遗留问题见 6.2：跨版式的证据装配、更强的多轮监督筛选，以及在原生结构感知压缩器上独立验证钉对的增量。

Financial numerical question answering asks a model to locate a few values in long financial reports and to compute with them; the answer is a number that can be checked. Compressing the evidence to fit a budget severs each value from its row header, column name and unit, so that the retained text may still contain the number yet no longer support recomputation. This paper addresses the problem in three progressive layers. The first layer changes the unit of retention: instead of ranking tokens, we keep anchor groups, namely a value together with the structural components that jointly explain it, under a closure constraint requiring that any retained value be accompanied by its whole group, so that what survives compression is itself an executable fact rather than an isolated digit. The second layer adds task relevance. Closure guarantees that a retained fact is self-consistent, not that it is the fact the question requires; a learned operand locator therefore pins the required pair into the budget before eviction, which separates structural completeness from task relevance and shows that neither constraint implies the other. The third layer moves computation out of the model: the reader emits a program that a whitelisted deterministic executor evaluates, so that arithmetic is no longer carried out on the generative side and errors in expression construction and evaluation no longer propagate silently. On single-step questions of FinQA, the three layers accumulate, and their relative weight depends on the compression budget: tight budgets are dominated by the first two layers, whereas loose budgets are dominated by the reading stage, so that the boundary between evidence retention and evidence reading shifts with the budget. The pinning layer requires no retraining and can be stacked onto existing attention-based compressors, which indicates that it can be deployed independently of the assembly pipeline used here. We also report where each layer fails and the conditions under which the conclusions do not transfer.
